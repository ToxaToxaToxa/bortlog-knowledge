# База знань Бортжурналу

Ознаки збоїв ArduPilot, які програма «Бортжурнал» (офлайн-аналізатор логів ArduPlane `.bin` і `.tlog`)
шукає в логах, і поради до її знахідок: підписи повідомлень автопілота, перевірки параметрів, поради з
умовами на параметри й виміряні факти, формулювання знахідок. Тут лише дані, жодного коду.

Програма при запуску у фоні завантажує `knowledge.json` з цього репозиторію і бере його, якщо файл
правильний і його `version` більша за ту, що вже є. Без інтернету вона працює з базою, яку має:
вбудованою в exe або завантаженою раніше. Аналіз завжди йде на вашому комп'ютері, без підписок.

## Файл

```json
{
  "format": 1,
  "version": 3,
  "entries": [ ... ]
}
```

- `format`: формат файлу. Програма відкидає файл із форматом, новішим за той, який знає.
- `version`: ціле число. **Збільшуйте його при кожній зміні**, інакше програми не візьмуть новий файл.
- `entries`: записи чотирьох типів: `message`, `param`, `advice`, `text`.

Файл містить лише дані: регулярні вирази, числа і тексти. Програма нічого з нього не виконує як код.
Запис із помилкою пропускається, решта працює. Завантажений з інтернету файл з хоч одним зіпсованим
записом не потрапляє в кеш. Виняток — записи, які може писати лише новіша версія програми: невідомий
тип, невідомий ключ знахідки, невідомий факт чи підстановка. Їх програма мовчки пропускає (видно в
підказці рядка стану і в кінці `--keys`), а файл приймає.

### Чому `format` лишився 1

Записи `advice` і `text` додано, не змінюючи `format`. Уже встановлені програми (до цієї версії)
пропускають записи невідомого типу навіть під час завантаження, тому новий файл вони приймають:
беруть з нього нові `message` і `param`, а поради показують свої, вбудовані в код. Якби `format`
став 2, старі програми відкинули б файл цілком і не отримували б навіть нових підписів повідомлень.
Побічний ефект: у старих програмах підказка на «база знань vN» перелічує записи `advice` і `text`
як пропущені («невідомий тип 'advice'»). Це не помилка.

`format` треба збільшувати лише тоді, коли зміниться зміст наявних полів так, що стара програма
прочитала б їх неправильно.

## Спільні поля записів `message` і `param`

| Поле | Обов'язкове | Значення |
|---|---|---|
| `id` | так | Унікальна назва запису латиницею, наприклад `sd_full` |
| `type` | так | `message` або `param` |
| `severity` | так | `crit`, `warn`, `info` або `ok` |
| `category` | так | Група під заголовком знахідки, наприклад «Система» |
| `title` | так | Заголовок знахідки |
| `detail` |  | Що саме видно в лозі |
| `advice` |  | Що робити |
| `plot` |  | Набір графіків, який відкриється: «Огляд», «Живлення», «EKF», «RC»… |
| `rule` |  | Назва правила для вердикту; за замовчуванням `id`. `flight_messages` вердикт вважає ознакою збою EKF |

## Запис `message`: підпис повідомлення автопілота

Шукає текст у повідомленнях STATUSTEXT (tlog) і MSG (bin).

| Поле | За замовчуванням | Значення |
|---|---|---|
| `pattern` | обов'язкове | Регулярний вираз Python. Без урахування регістру: почніть з `(?i)`. Іменована група `(?P<item>…)` задає частину тексту для `{item}` і `{items}` |
| `unless` | немає | Вираз-виняток: повідомлення, що під нього підходять, не враховуються |
| `when` | `any` | `any` — будь-коли, `armed` — лише armed, `in_air` — лише в повітрі |
| `group` | `same_text` | `each` — знахідка на кожне повідомлення; `same_text` — одна на однаковий текст (числа не враховуються); `all` — одна на всі |
| `detail_many` | немає | Текст `detail`, коли повідомлень у групі більше одного |
| `window` | немає | `[-10, 10]`: ділянка графіка в секундах від першого повідомлення |
| `mark_time` | `true` | Показувати час першого повідомлення в списку знахідок |
| `skip_near_disarm` | 0 | Не враховувати повідомлення ближче за стільки секунд до disarm у повітрі |
| `fallback` | `false` | Загальний запис: пропускає повідомлення, які вже впізнав якийсь конкретний запис |

Підстановки в `title`, `detail`, `detail_many`, `advice`:

- `{text}` — текст першого повідомлення групи, `{item}` — його група `item`;
- `{count}` — скільки повідомлень у групі, `{unique}` — скільки різних серед них;
- `{items}` — різні `item` через «; »;
- `{first}`, `{last}` — час першого й останнього (ХХ:СС).

## Запис `param`: перевірка параметра

```json
{
  "id": "batt_fs_off", "type": "param",
  "if": [{"param": "BATT_FS_LOW_ACT", "op": "==", "value": 0}],
  "severity": "info", "category": "Батарея",
  "title": "Батарейний failsafe вимкнено",
  "detail": "BATT_FS_LOW_ACT = {BATT_FS_LOW_ACT}.",
  "advice": "Поставте BATT_FS_LOW_ACT = 1 (RTL)."
}
```

`if` — список умов, мають виконатись усі. `op`: `==`, `!=`, `<`, `<=`, `>`, `>=`. Якщо параметра в лозі
немає, запис мовчить. У текстах можна підставити значення параметра з умов: `{BATT_FS_LOW_ACT}`.

## Ключі знахідок і факти

Кожна знахідка правил з коду і кожен рядок вердикту має ключ, наприклад `throttle.oscillation`,
`air_disarm.rc_glitch`, `battery.fs_off`, `verdict.log_end_no_cause`. Список ключів, факти кожного
і поради, які зараз дає база:

```
.venv\Scripts\python -m bortlog --keys
```

Ключі й факти визначені в `bortlog/knowledge/keys.py`. Факт — число, рядок або «немає» (не виміряно:
у тексті показується як «—», а умова з ним не виконується). Ключі `verdict.*` мають лише текст, без порад.

## Запис `advice`: порада до знахідки

```json
{
  "id": "throttle_slewrate", "type": "advice", "for": "throttle.oscillation",
  "if": [{"param": "THR_SLEWRATE", "op": ">=", "value": 80}],
  "order": 20,
  "text": "THR_SLEWRATE = {THR_SLEWRATE}%/с дозволяє різкі ривки: спробуйте 40–50."
}
```

| Поле | За замовчуванням | Значення |
|---|---|---|
| `id` | обов'язкове | Унікальна назва |
| `for` | обов'язкове | Ключ знахідки або список ключів: `["touchdown.crash", "touchdown.hard"]` |
| `text` | обов'язкове | Текст поради, закінчений крапкою |
| `if` | немає (завжди) | Умови, мають виконатись усі: `{"param": "ІМ'Я", "op": …, "value": число}` або `{"fact": "ім'я", "op": …, "value": число чи рядок}`. Рядок порівнюється лише через `==` / `!=` |
| `order` | 100 | Порядок у тексті поради; однакові — у порядку файлу |
| `fallback` | `false` | Показується, лише коли жодна звичайна порада цього ключа не підійшла |
| `replaces` | немає | Список `id` порад, які не показувати, коли ця підійшла |

Знахідка показує всі поради свого ключа, умови яких виконались, через пробіл у порядку `order`.
Параметра, якого немає в лозі, умова не виконується.

Підстановки в `text`: факти ключа (`{period}`, `{steady_thr}`…) і параметри з умов цього запису
(`{THR_SLEWRATE}`). Можна задати формат, як у Python: `{period:.1f}` — один знак після коми,
`{steady_thr:.0f}` — ціле. Без формату число показується найкоротше: `45`, `0.7`.
Для списку ключів у `for` доступні лише факти, спільні для всіх них.

Якщо в базі немає жодної поради для якогось ключа, програма бере поради цього ключа з вбудованої бази.

### Приклад: ще одна порада TECS при гойданні газу

```json
{
  "id": "throttle_tecs_thr_damp", "type": "advice", "for": "throttle.oscillation",
  "if": [{"param": "TECS_THR_DAMP", "op": "<", "value": 0.6},
         {"fact": "period", "op": ">", "value": 2}],
  "order": 30,
  "text": "TECS_THR_DAMP = {TECS_THR_DAMP} при періоді ≈{period:.1f} с: підніміть TECS_THR_DAMP до 0.7."
}
```

Загальна порада `throttle_tecs_default` (`fallback`) зникне сама, щойно підійде ця або інша конкретна.

## Запис `text`: формулювання знахідки або вердикту

```json
{
  "id": "throttle_oscillation_title", "type": "text", "key": "throttle.oscillation",
  "title": "Газ гойдається {thr_lo:.0f}–{thr_hi:.0f}%, період {period:.1f} с"
}
```

Замінює формулювання коду для ключа `key`. Поля `title`, `detail`, `severity` (`crit`, `warn`, `info`,
`ok`) — будь-які з них, решта лишається з коду. Підстановки — факти ключа, з форматом як у `advice`.
Для ключа може бути лише один запис `text`. Текст замінює весь рядок: частини, які код додає лише за
умови (наприклад «період ≈…», коли його вдалось визначити), у ньому треба писати через факти.

## Як додати запис

1. Для підпису повідомлення: знайдіть точний текст повідомлення в лозі (вкладка «Повідомлення»).
   Для поради: знайдіть ключ і його факти в `python -m bortlog --keys`.
2. Додайте запис у `entries`. Конкретний підпис ставте як звичайний запис: тоді загальний
   `flight_keywords` не покаже те саме повідомлення вдруге.
3. Збільште `version`.
4. Перевірте на лозі, де ця знахідка є, і на кількох звичайних:

   ```
   .venv\Scripts\python -m bortlog --text ЛОГ.BIN
   ```

   Пропущені записи видно в кінці `--keys` і в підказці на «база знань vN» у рядку стану.
5. Закомітьте тут і покладіть той самий файл у `bortlog-knowledge`: звідти його отримають уже
   встановлені програми без нового exe. Файли в обох репозиторіях мають бути однакові.
