# База знань Бортжурналу

Ознаки збоїв ArduPilot, які програма «Бортжурнал» (офлайн-аналізатор логів ArduPlane `.bin` і `.tlog`)
шукає в логах: підписи повідомлень автопілота і перевірки параметрів. Тут лише дані, жодного коду.

Програма при запуску у фоні завантажує `knowledge.json` з цього репозиторію і бере його, якщо файл
правильний і його `version` більша за ту, що вже є. Без інтернету вона працює з базою, яку має:
вбудованою в exe або завантаженою раніше. Аналіз завжди йде на вашому комп'ютері, без підписок.

## Файл

```json
{
  "format": 1,
  "version": 3,
  "entries": [ ... ]
}
```

- `format`: формат файлу. Програма відкидає файл із форматом, новішим за той, який знає.
- `version`: ціле число. **Збільшуйте його при кожній зміні**, інакше програми не візьмуть новий файл.
- `entries`: записи двох типів, `message` і `param`.

Файл містить лише дані: регулярні вирази, числа і тексти. Програма нічого з нього не виконує як код.
Запис із помилкою пропускається, решта працює. Завантажений з інтернету файл з хоч одним зіпсованим
записом не потрапляє в кеш (крім записів невідомого типу: їх пише новіша версія програми).

## Спільні поля

| Поле | Обов'язкове | Значення |
|---|---|---|
| `id` | так | Унікальна назва запису латиницею, наприклад `sd_full` |
| `type` | так | `message` або `param` |
| `severity` | так | `crit`, `warn`, `info` або `ok` |
| `category` | так | Група під заголовком знахідки, наприклад «Система» |
| `title` | так | Заголовок знахідки |
| `detail` |  | Що саме видно в лозі |
| `advice` |  | Що робити |
| `plot` |  | Набір графіків, який відкриється: «Огляд», «Живлення», «EKF», «RC»… |
| `rule` |  | Назва правила для вердикту; за замовчуванням `id`. `flight_messages` вердикт вважає ознакою збою EKF |

## Запис `message`: підпис повідомлення автопілота

Шукає текст у повідомленнях STATUSTEXT (tlog) і MSG (bin).

| Поле | За замовчуванням | Значення |
|---|---|---|
| `pattern` | обов'язкове | Регулярний вираз Python. Без урахування регістру: почніть з `(?i)`. Іменована група `(?P<item>…)` задає частину тексту для `{item}` і `{items}` |
| `unless` | немає | Вираз-виняток: повідомлення, що під нього підходять, не враховуються |
| `when` | `any` | `any` — будь-коли, `armed` — лише armed, `in_air` — лише в повітрі |
| `group` | `same_text` | `each` — знахідка на кожне повідомлення; `same_text` — одна на однаковий текст (числа не враховуються); `all` — одна на всі |
| `detail_many` | немає | Текст `detail`, коли повідомлень у групі більше одного |
| `window` | немає | `[-10, 10]`: ділянка графіка в секундах від першого повідомлення |
| `mark_time` | `true` | Показувати час першого повідомлення в списку знахідок |
| `skip_near_disarm` | 0 | Не враховувати повідомлення ближче за стільки секунд до disarm у повітрі |
| `fallback` | `false` | Загальний запис: пропускає повідомлення, які вже впізнав якийсь конкретний запис |

Підстановки в `title`, `detail`, `detail_many`, `advice`:

- `{text}` — текст першого повідомлення групи, `{item}` — його група `item`;
- `{count}` — скільки повідомлень у групі, `{unique}` — скільки різних серед них;
- `{items}` — різні `item` через «; »;
- `{first}`, `{last}` — час першого й останнього (ХХ:СС).

## Запис `param`: перевірка параметра

```json
{
  "id": "batt_fs_off", "type": "param",
  "if": [{"param": "BATT_FS_LOW_ACT", "op": "==", "value": 0}],
  "severity": "info", "category": "Батарея",
  "title": "Батарейний failsafe вимкнено",
  "detail": "BATT_FS_LOW_ACT = {BATT_FS_LOW_ACT}.",
  "advice": "Поставте BATT_FS_LOW_ACT = 1 (RTL)."
}
```

`if` — список умов, мають виконатись усі. `op`: `==`, `!=`, `<`, `<=`, `>`, `>=`. Якщо параметра в лозі
немає, запис мовчить. У текстах можна підставити значення параметра з умов: `{BATT_FS_LOW_ACT}`.

## Як додати запис

1. Знайдіть точний текст повідомлення в лозі (вкладка «Повідомлення»).
2. Додайте запис у `entries`. Конкретний підпис ставте як звичайний запис: тоді загальний
   `flight_keywords` не покаже те саме повідомлення вдруге.
3. Збільште `version`.
4. Перевірте на лозі, де це повідомлення є, і на кількох звичайних:

   ```
   .venv\Scripts\python -m bortlog --text ЛОГ.BIN
   ```

   Пропущені через помилки записи видно в підказці на «база знань vN» у рядку стану.
5. Закомітьте і запуште сюди: програми підхоплять новішу версію під час наступного запуску з інтернетом.
